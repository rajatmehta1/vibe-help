System Components

Backend (FastAPI / Python)

The backend is the central hub of ForgeLine. It exposes a RESTful API consumed by both the dashboard and the VS Code extension.

  • Framework: FastAPI with async support
  • Authentication: JWT token-based auth with user/organization model
  • AI Integration: Anthropic (Claude) and OpenAI APIs for code analysis
  • ORM: SQLAlchemy with async session management
  • Task Queue: Redis-backed background task processing for long-running scans
  • Port: 8000

Key modules:

  • app/api/ — Route handlers organized by resource (auth, projects, policies, scans)
  • app/models/ — SQLAlchemy ORM models
  • app/services/ — Business logic layer (scanning engine, policy evaluation, AI clients)
  • app/core/ — Configuration, security utilities, database connections
  • app/schemas/ — Pydantic request/response schemas

Dashboard (React / TypeScript / Tailwind)

A single-page application providing a visual interface for managing projects, configuring policies, viewing scan results, and monitoring compliance.

  • Framework: React 18+ with TypeScript
  • Styling: Tailwind CSS
  • Build Tool: Vite
  • Port: 3000 (production) / 5173 (Vite dev server)

Key pages:

  • Login / Registration
  • Project listing and detail views
  • Policy configuration per project
  • Scan results with severity filtering and line-level findings
  • Organization settings

VS Code Extension (TypeScript)

A VS Code extension that connects to the ForgeLine backend, enabling developers to scan code directly from their editor.

  • Language: TypeScript
  • Activation: On workspace open or manual trigger
  • Features: Scan on save, inline diagnostics, severity threshold filtering

Extension settings:

Setting Type Description
forgeline.serverUrl string URL of the ForgeLine backend API
forgeline.apiKey string API key for authentication
forgeline.projectId string ID of the project to scan against
forgeline.autoScan boolean Enable automatic scanning
forgeline.scanOnSave boolean Trigger a scan every time a file is saved
forgeline.severityThreshold string Minimum severity level to display (info, warning, error, critical)

Database Schemas

PostgreSQL Schema

-- Users
CREATE TABLE users (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email         VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    full_name     VARCHAR(255),
    org_id        UUID REFERENCES organizations(id),
    created_at    TIMESTAMPTZ DEFAULT now(),
    updated_at    TIMESTAMPTZ DEFAULT now()
);

-- Organizations
CREATE TABLE organizations (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(255) NOT NULL,
    slug        VARCHAR(255) UNIQUE NOT NULL,
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- Projects
CREATE TABLE projects (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(255) NOT NULL,
    description TEXT,
    org_id      UUID REFERENCES organizations(id) NOT NULL,
    created_by  UUID REFERENCES users(id),
    created_at  TIMESTAMPTZ DEFAULT now(),
    updated_at  TIMESTAMPTZ DEFAULT now()
);

-- Policies
CREATE TABLE policies (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(255) NOT NULL,
    slug        VARCHAR(100) UNIQUE NOT NULL,
    description TEXT,
    category    VARCHAR(100) NOT NULL,
    rules       JSONB NOT NULL DEFAULT '{}',
    is_builtin  BOOLEAN DEFAULT false,
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- Project-Policy association
CREATE TABLE project_policies (
    project_id  UUID REFERENCES projects(id) ON DELETE CASCADE,
    policy_id   UUID REFERENCES policies(id) ON DELETE CASCADE,
    enabled     BOOLEAN DEFAULT true,
    severity    VARCHAR(20) DEFAULT 'warning',
    config      JSONB DEFAULT '{}',
    PRIMARY KEY (project_id, policy_id)
);

-- Scans
CREATE TABLE scans (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id  UUID REFERENCES projects(id) NOT NULL,
    user_id     UUID REFERENCES users(id),
    status      VARCHAR(20) DEFAULT 'pending',
    file_name   VARCHAR(500),
    language    VARCHAR(50),
    code_hash   VARCHAR(64),
    started_at  TIMESTAMPTZ,
    completed_at TIMESTAMPTZ,
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- Scan Results / Findings
CREATE TABLE findings (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    scan_id     UUID REFERENCES scans(id) ON DELETE CASCADE,
    policy_id   UUID REFERENCES policies(id),
    severity    VARCHAR(20) NOT NULL,
    message     TEXT NOT NULL,
    line_start  INT,
    line_end    INT,
    suggestion  TEXT,
    embedding   vector(1536),
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- Index for vector similarity search
CREATE INDEX ON findings USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

Neo4j Graph Model

    (Organization)---[:HAS_PROJECT]--->(Project)
         |                                 |
    [:HAS_MEMBER]                   [:HAS_POLICY]
         |                                 |
       (User)                          (Policy)
         |                                 |
    [:INITIATED]                   [:VIOLATED_BY]
         |                                 |
       (Scan)----[:PRODUCED]-------->(Finding)

Node types: Organization, User, Project, Policy, Scan, Finding

Relationship types: HAS_PROJECT, HAS_MEMBER, HAS_POLICY, INITIATED, PRODUCED, VIOLATED_BY, SIMILAR_TO

API Design Principles

  • RESTful: Resources are nouns, HTTP methods indicate actions (GET, POST, PUT, DELETE)
  • Versioned: All endpoints are prefixed with /api/v1/
  • Consistent responses: All endpoints return JSON with a predictable envelope structure
  • Pagination: List endpoints support ?page= and ?per_page= query parameters
  • Error format: Errors return {"detail": "message"} with appropriate HTTP status codes
  • Authentication: Bearer token in the Authorization header for protected endpoints
  • OpenAPI: Auto-generated Swagger documentation available at /docs

See the API Reference for full endpoint documentation.
