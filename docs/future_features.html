Future Features (Phase 2 Roadmap)

This document outlines the planned features and enhancements for ForgeLine Phase 2. These items are currently out of scope for the initial release but represent the next major iteration of the platform.

CI/CD Integration

Planned

Integrate ForgeLine scanning directly into continuous integration and deployment pipelines so that policy checks run automatically on every commit or pull request.

Planned Capabilities

  • GitHub Actions — Official action that runs ForgeLine scans as a workflow step and reports findings as check annotations
  • GitLab CI — Template job definition for .gitlab-ci.yml integration
  • Jenkins — Pipeline plugin for triggering scans from Jenkinsfiles
  • Generic CLI — A forgeline-cli tool that can be used in any CI system, exiting with non-zero status when critical findings are detected

Expected Behavior

  • Scan changed files only (diff-based) for faster pipeline execution
  • Configurable failure thresholds (e.g., fail the build if any critical or error-severity findings exist)
  • SARIF output format for compatibility with GitHub Code Scanning and other tools
  • Caching of previous scan results to avoid redundant analysis

GitHub Pull Request Bot

Planned

A GitHub App that automatically reviews pull requests, posting inline comments on lines that violate enabled policies.

Planned Capabilities

  • Automatic scan triggered on PR open and update events
  • Inline review comments on specific lines with violation details and remediation suggestions
  • Summary comment with overall compliance score and finding counts by severity
  • Status check that blocks merging if critical violations are found
  • Configuration via .forgeline.yml in the repository root

Custom LLM Rules

Planned

Allow users to define custom analysis rules using natural language prompts, expanding beyond the 7 built-in policy templates.

Planned Capabilities

  • Natural language rule editor in the dashboard
  • Rule testing sandbox where users can validate rules against sample code
  • Rule versioning and rollback
  • Ability to share custom rules across projects within an organization
  • Template library for common custom rules contributed by the community

Example Custom Rule

{
  "name": "No Direct Database Queries in Controllers",
  "prompt": "Check if this code file, which appears to be a controller or route handler, contains any direct database queries (SQL statements, ORM queries, or direct database client calls). Controllers should delegate data access to a service or repository layer.",
  "severity": "warning",
  "languages": ["python", "typescript", "javascript"]
}

Team Management

Planned

Enhanced organization and team management features for larger teams adopting ForgeLine.

Planned Capabilities

  • Roles and permissions — Admin, Manager, Developer, and Viewer roles with granular permissions
  • Team grouping — Organize users into teams within an organization, with per-team project access
  • SSO / SAML — Single sign-on integration with identity providers (Okta, Azure AD, Google Workspace)
  • Audit log — Detailed log of all user actions for compliance and security review
  • Usage analytics — Per-user and per-team scan statistics, compliance trends, and adoption metrics

Webhooks

Planned

Outbound webhook support for integrating ForgeLine events with external systems.

Planned Events

Event Trigger Use Case
scan.completed A scan finishes processing Notify Slack, update JIRA ticket
scan.critical_finding A critical-severity finding is detected Page on-call engineer via PagerDuty
project.policy_changed A policy is enabled, disabled, or reconfigured Log policy changes for audit
project.created A new project is created Auto-provision default policies

Webhook Payload Format

{
  "event": "scan.completed",
  "timestamp": "2026-01-15T10:30:00Z",
  "data": {
    "scan_id": "uuid",
    "project_id": "uuid",
    "status": "completed",
    "findings_count": 5,
    "critical_count": 1,
    "error_count": 2,
    "warning_count": 2
  }
}

VS Code Marketplace Publishing

Planned

Publish the ForgeLine VS Code extension to the Visual Studio Marketplace for easy discovery and one-click installation.

Planned Steps

  • Register a verified publisher account on the VS Code Marketplace
  • Set up automated CI/CD pipeline to build and publish new versions
  • Add extension icon, screenshots, and detailed README
  • Implement automatic update notifications within the extension
  • Support Open VSX Registry for VS Codium and other open-source editor users

Additional Phase 2 Items

Multi-Language Expansion

Expand language-specific analysis support beyond the initial set, with dedicated rule sets for Go, Rust, Java, C#, Ruby, and PHP.

Self-Hosted LLM Support

Allow organizations to run their own LLM inference (e.g., via Ollama, vLLM, or HuggingFace TGI) for code analysis, eliminating the need to send code to third-party APIs.

Dashboard Enhancements

  • Compliance trend charts and historical reporting
  • Diff view showing code before and after applying suggestions
  • Export scan reports to PDF and CSV
  • Dark/light theme toggle (currently dark only)

Policy Marketplace

A community-driven marketplace where teams can share and discover custom policy templates, similar to ESLint shared configs or Prettier plugins.
