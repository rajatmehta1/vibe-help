Deploy Without Docker

This guide covers manual installation and deployment of all ForgeLine components without Docker. This is useful for production environments where you want full control over each service, or for development on machines where Docker is not available.

Overview

You will install and configure the following components:

  1. PostgreSQL 15+ with the pgvector extension
  2. Neo4j 5+ for the knowledge graph
  3. Redis 7+ for caching and the task queue
  4. Python backend (FastAPI application)
  5. React dashboard (static build served by a web server)

1. Install PostgreSQL with pgvector

Ubuntu / Debian

# Install PostgreSQL
sudo apt update
sudo apt install -y postgresql-15 postgresql-contrib-15

# Install pgvector from source
sudo apt install -y postgresql-server-dev-15 build-essential git
cd /tmp
git clone --branch v0.5.1 https://github.com/pgvector/pgvector.git
cd pgvector
make
sudo make install

# Start PostgreSQL
sudo systemctl enable postgresql
sudo systemctl start postgresql

macOS (Homebrew)

brew install postgresql@15
brew install pgvector

brew services start postgresql@15

Windows

# Download the installer from https://www.postgresql.org/download/windows/
# Run the installer and include pgvector from Stack Builder,
# or build pgvector from source using Visual Studio Build Tools.

Create the Database and Enable pgvector

# Switch to postgres user
sudo -u postgres psql

-- Create user and database
CREATE USER forgeline WITH PASSWORD 'your-db-password';
CREATE DATABASE forgeline OWNER forgeline;

-- Connect to the database and enable pgvector
\c forgeline
CREATE EXTENSION IF NOT EXISTS vector;

-- Grant permissions
GRANT ALL PRIVILEGES ON DATABASE forgeline TO forgeline;
\q

Verify

psql -U forgeline -d forgeline -h localhost -c "SELECT extname FROM pg_extension WHERE extname = 'vector';"

Expected output: one row showing vector.

2. Install Neo4j

Ubuntu / Debian

# Add Neo4j repository
wget -O - https://debian.neo4j.com/neotechnology.gpg.key | sudo gpg --dearmor -o /usr/share/keyrings/neo4j.gpg
echo "deb [signed-by=/usr/share/keyrings/neo4j.gpg] https://debian.neo4j.com stable latest" | sudo tee /etc/apt/sources.list.d/neo4j.list
sudo apt update

# Install Neo4j
sudo apt install -y neo4j

# Start Neo4j
sudo systemctl enable neo4j
sudo systemctl start neo4j

macOS (Homebrew)

brew install neo4j
brew services start neo4j

Windows

# Download from https://neo4j.com/download-center/
# Run the installer or extract the ZIP and run bin\neo4j console

Configure Neo4j

Edit the Neo4j configuration file (typically /etc/neo4j/neo4j.conf):

# Set the initial password (or use the Neo4j Browser at http://localhost:7474)
sudo neo4j-admin dbms set-initial-password your-neo4j-password

# Ensure these settings are configured:
# server.default_listen_address=0.0.0.0
# server.bolt.listen_address=:7687
# server.http.listen_address=:7474

Verify

cypher-shell -u neo4j -p your-neo4j-password "RETURN 1 AS test;"

Access the Neo4j Browser at http://localhost:7474.

3. Install Redis

Ubuntu / Debian

sudo apt update
sudo apt install -y redis-server

# Enable and start
sudo systemctl enable redis-server
sudo systemctl start redis-server

macOS (Homebrew)

brew install redis
brew services start redis

Windows

# Option 1: Install via WSL2 (recommended)
# Option 2: Use Memurai (Redis-compatible for Windows): https://www.memurai.com/
# Option 3: Download from https://github.com/microsoftarchive/redis/releases

Verify

redis-cli ping

Expected output: PONG

4. Configure and Run the Python Backend

Step 1: Set up the Python environment

cd backend

# Create virtual environment
python3 -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

Step 2: Create the environment file

Create a .env file in the backend/ directory:

# PostgreSQL - use localhost since not in Docker
DATABASE_URL=postgresql+asyncpg://forgeline:your-db-password@localhost:5432/forgeline

# Neo4j
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your-neo4j-password

# Redis
REDIS_URL=redis://localhost:6379/0

# Auth
JWT_SECRET=generate-a-strong-random-string-here

# AI Providers
ANTHROPIC_API_KEY=sk-ant-your-key-here
OPENAI_API_KEY=sk-your-key-here

Step 3: Run database migrations

alembic upgrade head

Step 4: Seed built-in policies

python -m app.scripts.seed_policies

Step 5: Start the backend

For development:

uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

For production, use Gunicorn with Uvicorn workers:

gunicorn app.main:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:8000

Verify

Open http://localhost:8000/docs to see the Swagger UI.

5. Build and Serve the Dashboard

Step 1: Install dependencies and build

cd dashboard

# Install dependencies
npm install

# Set the API URL for the build
echo "VITE_API_URL=http://localhost:8000" > .env.production

# Build the production bundle
npm run build

The build output will be in the dist/ directory.

Step 2: Serve with Nginx

Install Nginx and create a site configuration:

sudo apt install -y nginx

Create /etc/nginx/sites-available/forgeline-dashboard:

server {
    listen 3000;
    server_name _;

    root /path/to/forgeline/dashboard/dist;
    index index.html;

    # SPA routing - serve index.html for all routes
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Proxy API requests to the backend
    location /api/ {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
# Enable the site
sudo ln -s /etc/nginx/sites-available/forgeline-dashboard /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

Alternative: Serve with Node.js

# Install serve globally
npm install -g serve

# Serve the built dashboard
serve -s dist -l 3000

6. Set Up systemd Services (Linux)

For production deployments on Linux, create systemd service files to manage the ForgeLine backend as a system service.

Backend Service

Create /etc/systemd/system/forgeline-backend.service:

[Unit]
Description=ForgeLine Backend API
After=network.target postgresql.service redis-server.service neo4j.service
Wants=postgresql.service redis-server.service neo4j.service

[Service]
Type=simple
User=forgeline
Group=forgeline
WorkingDirectory=/opt/forgeline/backend
Environment="PATH=/opt/forgeline/backend/venv/bin:/usr/bin"
EnvironmentFile=/opt/forgeline/backend/.env
ExecStart=/opt/forgeline/backend/venv/bin/gunicorn app.main:app \
    -w 4 \
    -k uvicorn.workers.UvicornWorker \
    --bind 0.0.0.0:8000 \
    --access-logfile /var/log/forgeline/access.log \
    --error-logfile /var/log/forgeline/error.log
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

Enable and Start

# Create the forgeline user
sudo useradd -r -s /bin/false forgeline

# Create log directory
sudo mkdir -p /var/log/forgeline
sudo chown forgeline:forgeline /var/log/forgeline

# Enable and start the service
sudo systemctl daemon-reload
sudo systemctl enable forgeline-backend
sudo systemctl start forgeline-backend

# Check status
sudo systemctl status forgeline-backend

Dashboard Service (using serve)

Create /etc/systemd/system/forgeline-dashboard.service:

[Unit]
Description=ForgeLine Dashboard
After=network.target

[Service]
Type=simple
User=forgeline
Group=forgeline
WorkingDirectory=/opt/forgeline/dashboard
ExecStart=/usr/bin/npx serve -s dist -l 3000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable forgeline-dashboard
sudo systemctl start forgeline-dashboard

7. Firewall Configuration

If running on a server, configure firewall rules to expose only the necessary ports:

# Allow dashboard and API
sudo ufw allow 3000/tcp   # Dashboard
sudo ufw allow 8000/tcp   # Backend API (or proxy through Nginx on 80/443)

# Keep databases internal only (do NOT expose to the internet)
# PostgreSQL: 5432 - internal only
# Neo4j: 7474, 7687 - internal only
# Redis: 6379 - internal only

sudo ufw enable

For production, serve both the dashboard and API behind a reverse proxy (Nginx or Caddy) on ports 80/443 with TLS.

Port Reference

Service Port Exposed? Notes
Backend API 8000 Yes (or via proxy) FastAPI with Gunicorn + Uvicorn workers
Dashboard 3000 Yes (or via proxy) Static build served by Nginx or serve
PostgreSQL 5432 No (internal) Only accessible from backend
Neo4j HTTP 7474 No (internal) Browser UI for administration
Neo4j Bolt 7687 No (internal) Binary protocol for queries
Redis 6379 No (internal) Cache and task queue

Troubleshooting

PostgreSQL: pgvector extension not found

Make sure you installed pgvector and ran CREATE EXTENSION vector; inside the target database. Verify with:

psql -U forgeline -d forgeline -c "SELECT * FROM pg_extension WHERE extname = 'vector';"

Neo4j: Connection refused on port 7687

Check that Neo4j is running and the Bolt connector is enabled:

sudo systemctl status neo4j
grep "bolt" /etc/neo4j/neo4j.conf

Redis: Connection refused

Ensure Redis is running and listening on the expected interface:

sudo systemctl status redis-server
redis-cli -h localhost -p 6379 ping

Backend: ModuleNotFoundError

Ensure the virtual environment is activated and all dependencies are installed:

source venv/bin/activate
pip install -r requirements.txt

Dashboard: Blank page after build

Check that VITE_API_URL was set correctly before building, and that the Nginx try_files directive is configured for SPA routing.
